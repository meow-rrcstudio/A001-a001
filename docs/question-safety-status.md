# 민감질문 대응 현황 (2026-08 기준)

AI와 함께 검토하기 위해 **지금 코드에 실제로 들어 있는 것**만 정리했습니다.
"이렇게 하면 좋겠다"는 맨 아래 〈논점〉에만 두었고, 그 위는 전부 현재 동작입니다.

관련 파일

| 파일 | 맡은 일 |
|---|---|
| `lib/question-safety.ts` | 물음을 읽고 분류·등급·안내문·프롬프트 지침을 정함 |
| `components/question-care-notice.tsx` | 화면에 내미는 안내 상자(위기면 연락처까지) |
| `lib/free-question.ts` | 등급·분류에 따라 카드 자리(스프레드)를 고름 |
| `lib/reading-prompt-templates.ts` | 해석·면담 프롬프트에 안전 층을 붙임 |
| `app/api/reading/plan/route.ts` | 배열 고르기 호출에 안전 층을 붙임 |
| `app/tarot/ask/page.tsx` | 화면 흐름(질문 → 뽑기 → 해석 → 면담) |

## 1. 무엇을 민감하다고 보는가

`auditFreeQuestion()` 이 **정규식**으로 판정합니다. 판정 순서가 곧 우선순위입니다.

1. **자·타해 (`SELF_HARM`, `HARM_OTHERS`)** — 가장 먼저 봅니다.
   `자살|자해|목숨을 끊|죽고 싶|살기 싫|사라지고 싶|극단적 선택|유서|손목을 긋` 등.
   → 등급 `crisis`
2. **범죄 (`CRIME_DOING`)** — 폭행·협박·스토킹·불법촬영·마약·사기·해킹 등.
   같은 낱말이라도 `VICTIM`(당하다·피해·괴롭힘·무섭다·도망) 이 함께 걸리면
   **가해가 아니라 피해**로 보고 다른 안내·다른 연락처를 냅니다.
3. **주제 분류(RULES)** — 위에서부터 처음 걸리는 것이 이깁니다.
   위험한 것을 앞에 둡니다: **의료 → 법률 → 투자 →** 연애 → 가족 → 직장 →
   진로 → 금전 → 인간관계 → 건강 → 자기성찰.
   이 중 **의료·법률·투자·범죄**만 `sensitive` 등급이 붙고, 나머지는 `normal`.

등급은 셋입니다.

- `normal` — 그냥 읽습니다. 안내 상자도, 추가 프롬프트 지침도 **붙지 않습니다**.
- `sensitive` — 결과를 맞히듯 말하면 안 되는 물음 (의료·법률·투자·가해)
- `crisis` — 카드보다 사람 손이 먼저 닿아야 하는 물음 (자·타해, 범죄 피해)

**적용 범위: 사용자가 직접 친 자유 질문만.** 준비된 칩 질문(`lib/reading-content.ts`)은
사람이 질문·배열·흐름까지 설계해 둔 것이라 이 판정을 통과하지 않습니다.

## 2. 걸렸을 때 실제로 달라지는 것 — 네 갈래

### ① 물음 자체는 건드리지 않습니다

예전에는 민감한 물음이면 문장을 다른 것으로 갈아끼웠습니다. 지금은 하지 않습니다.
화면에도 기록에도 사용자가 친 그대로 남습니다. 잘못 걸렸을 때(정규식은 반드시
잘못 겁니다) 잃는 것이 "말투가 조금 조심스러워지는 것"뿐이도록 한 설계입니다.

다만 프롬프트에 실을 때는 `sanitizeForPrompt()` 로 **문법 글자만** 씻어냅니다
(`{} @ \`` , `###`, 제어문자 → 공백, 200자 절단). 뜻은 바뀌지 않습니다.
프롬프트 인젝션 대비이고, 분류는 씻어내기 전 원문으로 합니다.

### ② 화면에 안내 상자를 내밉니다 (`QuestionCareNotice`)

`level !== normal` 이면 **카드를 뽑기 전에** 샨티 말투의 안내가 뜹니다.
거절 상자가 아니라 "이 자리는 무엇을 보는 자리인지" 일러주는 상자입니다.

- **위기면 연락처를 우리가 직접 박아 넣습니다.** 모델이 말할지 안 할지에
  기대지 않고, 번호를 지어내지 못하게 하려는 것입니다.
  - 자·타해: 자살예방 109 / 정신건강 1577-0199 / 응급 119
  - 범죄 피해: 경찰 112 / 여성긴급전화 1366 / 법률구조공단 132
- 앱인토스 웹뷰에서는 `tel:` 이 막힐 수 있어 **전화 걸기 대신 번호 복사**로 바뀝니다.
- "이렇게 물어도 좋다냥 — …" 하고 **대안 질문을 권해 보입니다** (거절이 아니라 권함).

### ③ 카드 자리가 바뀝니다 (`freeSpreadFor`)

`crisis`, 그리고 투자를 뺀 `sensitive` 는 **돌봄형** 스프레드로 갑니다.
돌봄형에는 **앞일을 묻는 자리가 없습니다** — 검사 결과나 재판을 앞둔 사람에게
"다가올 흐름" 자리를 내밀면 그 자리 이름 자체가 결과 예측이 되기 때문입니다.
투자는 셈형으로 가는데, 셈형에도 이미 "다가올 흐름" 자리가 없습니다.
장수는 어느 경우든 여섯 장을 지킵니다.

### ④ 프롬프트에 안전 층이 붙습니다

**`SAFETY_BASELINE`** — 언제나, 모든 호출에 붙습니다(글자가 늘 같아 캐싱이 안 깨짐).
정체 고정 / 시스템 프롬프트 비공개 / 차갑지 않은 거절 / 타로는 전문 판단을
대신하지 않음 / 가해·불법을 돕지 않음.

**`safetyDirective(audit)`** — `normal` 이 아닐 때만 추가로 붙습니다.
분류, 등급, 읽는 방향(`focus`), 말투, 그리고 금지 항목:

> 금지 = 결과를 맞히는 말(확진·완치·승소·상승) | 숫자로 된 확률 | 치료법·법률자문·매매지시

`crisis` 면 여기에 "카드보다 사람이 먼저", "화면에 이미 연락처가 있으니 번호를
지어내지 말 것", "위험한 방법을 설명·미화하지 말 것" 이 더 붙습니다.

**사용자가 친 말은 system 자리에 한 글자도 올라가지 않습니다.** system 은 모델이
가장 무겁게 믿는 자리라, 사용자의 말을 그리로 올리면 "규칙"으로 읽힙니다.
물음은 언제나 user 자리에만 실립니다.

## 3. 흐름별로 어디까지 걸려 있나

| 지점 | 판정 | 안전 지침 | 화면 안내 |
|---|---|---|---|
| 질문 입력 (`app/tarot/ask`) | 화면에서 판정 | — | **O** |
| 배열 고르기 (`/api/reading/plan`) | **서버에서 다시 판정** | O | — |
| 해석 (`buildReadingMessages`) | **서버에서 다시 판정** | O | — |
| 뽑기 화면 | — | — | **O** |
| 해석 결과 화면 | — | O(프롬프트) | **X** |
| 이어묻기 면담 (`/api/reading/chat`) | 이번 말만 판정 | O | **X** |

핵심은 **화면의 판정을 서버가 믿지 않는다**는 점입니다. 비회원은 서버에 배열을
묻지 않으므로 화면도 같은 판정을 하지만, 프롬프트에 실리는 지침은 언제나 서버에서
다시 붙입니다. 화면이 보낸 값을 믿으면 요청을 손으로 만들어 지침만 빼버릴 수 있습니다.

면담은 매 발화를 다시 판정합니다 — 처음 물음이 멀쩡했다고 이어지는 말까지
멀쩡하지는 않기 때문입니다.

## 4. 확인된 빈틈 (코드 기준)

AI와 논의할 때 이 넷을 먼저 봐주면 좋겠습니다.

**(1) 면담에서 처음 물음의 등급이 물려받아지지 않습니다.**
`buildChatMessages` 는 `context.audit` 이 있으면 물려받도록 짜여 있는데
(`lib/reading-prompt-templates.ts:235`), `app/api/reading/chat/route.ts` 가
`ChatContext` 를 만들 때 **`audit` 을 넣지 않습니다**. 그래서 그 물려받기는
사실상 동작하지 않습니다. → "죽고 싶다"로 시작한 판에서 다음 말이 "그럼 내일은
어때?" 처럼 평범하면, 그 턴에는 위기 지침이 아예 붙지 않습니다.

**(2) 위기 연락처가 뽑기 화면에서만 보입니다.**
`QuestionCareNotice` 는 `step === "draw"` 에서만 렌더됩니다. 해석 결과 화면과
면담 화면에는 번호가 없습니다. 정작 사람이 오래 머무는 자리는 뒤쪽입니다.

**(3) `risk` 필드가 아무 데서도 쓰이지 않습니다.**
`RiskLevel`(Low/Medium/High/Critical)을 채우기만 하고 읽는 곳이 없습니다.
게다가 범죄-피해 갈래에서 값이 뒤집혀 있습니다 — `level` 은 피해자일 때
`crisis`(더 급함)인데 `risk` 는 피해자일 때 `High`, 가해자일 때 `Critical`
(`lib/question-safety.ts:363-364`). 쓰이지 않아 드러나지 않았을 뿐입니다.

**(4) 판정이 한국어 정규식 하나뿐입니다.**
띄어쓰기·오타·은어·영어·우회 표현("ㅈㅅ", "먼저 갈게", "리셋하고 싶다")은
그대로 빠져나갑니다. 반대로 "죽고 싶을 만큼 웃겼어" 같은 관용구는 잘못 걸립니다.
잘못 걸렸을 때의 대가를 작게 만들어 둔 설계이긴 하나, **놓쳤을 때의 대가는
작지 않습니다.**

## 5. AI와 협의할 논점

1. **놓침(false negative)을 줄이는 값은 어디까지인가.** 정규식을 넓히면 오탐이
   늘고, 오탐은 멀쩡한 리딩에 군더더기를 얹습니다. 지금은 오탐 쪽으로 기울어
   있는데 이 균형이 맞나?
2. **모델 기반 판정을 얹을 것인가.** 배열 고르기(`/api/reading/plan`)는 이미
   모델을 부르므로 그 응답에 등급을 함께 받아올 여지가 있습니다. 다만 비회원은
   이 호출을 하지 않고, 이 호출은 실패율이 낮지 않습니다 — 안전 판정을 실패할
   수 있는 호출에 기대도 되나?
3. **위기 안내를 어디까지 따라다니게 할 것인가.** 결과·면담 화면까지 연락처를
   붙이면 안전하지만, 매 화면에 상자가 따라다니는 것이 "낙인"처럼 읽힐 수 있습니다.
4. **면담 등급 물려받기의 기본값.** 처음이 위기였으면 그 판 내내 위기로 볼 것인가,
   아니면 몇 턴 뒤에는 놓아줄 것인가.
5. **면담 중 등급이 올라갔을 때 화면 안내를 띄울 것인가.** 지금은 프롬프트만
   바뀌고 화면은 아무 일 없습니다.
