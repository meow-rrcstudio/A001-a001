# 로그인 — 어떤 경우에 무엇이 보이는가

이메일 로그인은 "로그인"과 "가입"이 한 화면입니다. 그래서 갈래가 많고,
갈래마다 사람이 갇히지 않는지 확인해야 합니다. 실제로 갇혔던 적이 있습니다.

## 왜 한 화면인가

Supabase 는 "비밀번호가 틀렸다"와 "그런 계정이 없다"를 **구분해 주지
않습니다.** 일부러 그렇습니다 — 구분해 주면 아무 주소나 넣어보며 누가
가입했는지 알아낼 수 있습니다.

그래서 이렇게 합니다.

```
① 먼저 로그인해 본다 → 되면 끝
② "자격 증명이 틀렸다"고 하면, 비번이 틀렸거나 계정이 없거나 둘 중 하나
③ 그러면 가입을 시도해 본다 → 이미 있으면 그때 알게 되고, 없으면 인증 메일이 나간다
```

## 흐름

```
                    [이메일 · 비밀번호 입력]
                              │
                              ▼
                     supabase.signInWithPassword
                              │
          ┌───────────────────┼────────────────────┐
          │                   │                    │
        성공                오류                 응답 없음
          │                   │                    │
          ▼                   ▼                    ▼
      ✅ 들어감      ┌─ 자격증명 오류인가? ─┐    ⓘ "응답이 없어요"
                     │                      │        + 길 둘
                    아니오                  예
                     │                      │
                     ▼                      ▼
            ⚠️ 인증 전 계정 등        supabase.signUp
               + 길 둘                      │
                              ┌─────────────┼──────────────┬───────────┐
                              │             │              │           │
                        이미 있는 계정   그 밖 오류    세션 받음    메일 나감
                              │             │              │           │
                              ▼             ▼              ▼           ▼
                     ⚠️ "비밀번호가     ⚠️ 사유 표시    ✅ 들어감   ⓘ "인증 메일이
                        맞지 않아요"      + 길 둘      (메일확인      전송됐어요"
                        + 길 둘                        꺼둔 경우)     + 길 둘
```

**길 둘** = `인증 메일 다시 받기` · `비밀번호 찾기`

## 경우별로 보이는 것

| 상황 | 글씨 | 누를 수 있는 것 |
|---|---|---|
| 로그인 성공 | — | (바로 이동) |
| 비밀번호 틀림 (계정 있음) | 비밀번호가 맞지 않아요 | 길 둘 |
| 계정 없음 → 가입됨 | 가입을 위해 입력한 이메일로 인증 메일이 전송되었어요 / 메일이 오지 않으면 주소를 다시 확인해 주세요 | 길 둘 |
| **인증 전 계정으로 로그인** | 메일함에서 인증 링크를 먼저 눌러주세요 | 길 둘 |
| **메일 발송 제한에 걸림** | 메일을 너무 자주 보냈어요 | 길 둘 |
| 응답 없음(시간 초과) | 응답이 없어요 | 길 둘 |
| 인증 메일 재전송 성공 | 인증 메일을 다시 보냈어요 | 길 둘 |
| 비밀번호 재설정 메일 발송 | 비밀번호를 새로 정하는 링크를 보냈어요 | 길 둘 |

⚠️ **"어떤 오류에는 어떤 단추"를 하나하나 정하지 않습니다.** 그렇게 두면
새 갈래가 생길 때마다 단추 다는 것을 잊고, 그 갈래에 걸린 사람이 갇힙니다.
이메일이 적혀 있으면 두 길을 늘 냅니다 — 둘 다 눌러도 해롭지 않습니다.

### 예전에 갇혔던 자리 (고쳤습니다)

1. **인증 전 계정으로 다시 로그인** — 재전송 단추가 `info` 상태에만 붙어
   있어서, 오류로 떨어지는 이 갈래에서는 아무 단추도 없었습니다. 가입
   직후 한 번은 보이는데 새로고침하면 사라져서, "두 번쯤 하면 없어진다"로
   보였습니다.
2. **가입 시도가 메일 발송 제한에 걸림** — 사유만 뜨고 단추가 없었습니다.
3. **재전송이 제한에 걸림** — 단추가 사라져서 잠시 뒤 다시 누를 수 없었습니다.
4. **비밀번호가 조건에 안 맞음** — 문구 한 줄만 뜨고 단추가 없었습니다.
   여기 오는 사람의 절반은 **이미 계정이 있는 사람**입니다. 비밀번호가
   틀려서 가입 시도로 넘어왔는데, 그 틀린 비밀번호가 지금 조건에 안 맞으면
   이리로 떨어집니다. 옛 계정은 지금 조건을 지나지 않았을 수 있어서 흔한
   일인데, 화면에는 "이렇게 정해야 한다"는 말만 있고 되찾을 길이 없었습니다.
5. **칸을 비우고 단추를 누름** — 조용히 아무 일도 안 했습니다
   (재전송·비밀번호 찾기·다시 로그인 셋 다). 누른 사람에게는 고장으로
   보입니다.

## ⚠️ 비밀번호 조건은 한 곳에서만 정합니다

`lib/password-policy.ts` — 최소 길이와 문구가 여기 있고, 세 화면이 이걸
함께 씁니다.

| 자리 | 조건을 보는가 |
|---|---|
| 가입 (로그인 화면에서 새 계정) | ✅ 봅니다 |
| **비밀번호 재설정** (`/reset-password`) | ✅ 봅니다 |
| 로그인 | ❌ 보지 않습니다 — 옛 계정이 지금 조건을 안 지날 수 있고, 여기서 막으면 자기 계정에 못 들어갑니다 |

### 대시보드 값 (2026-08-07 확인)

Authentication → Providers → Email → Password Requirements

| 항목 | 값 |
|---|---|
| Minimum password length | **8** |
| Password requirements | **Lowercase, uppercase letters, digits and symbols** |

`lib/password-policy.ts` 와 같습니다. **다시 여쭤보지 마세요** — 이 값을
바꿀 때만 양쪽을 함께 고치면 됩니다.

한때 세 곳이 서로 다른 말을 했습니다 — 정책은 8자인데 재설정 화면은
"6자 이상"이라 적어두고 6자를 받았고, 서버가 옮긴 오류도 "6자"라고
했습니다. 화면이 시킨 대로 했는데 Supabase 가 막는 상태였습니다.

## 물음표 — "로그인이 왜 이렇게 물어보나요?"

`components/login-help.tsx`. 동의 고지 아래에 늘 있습니다 (오류가 나야
보이는 것이 아닙니다).

여기서 답하는 것은 두 가지입니다.

1. **의심** — 인증 메일이 `supabase.co` 에서 옵니다. 처음 보는 사람에게는
   "여기 가입하면 정보가 어디로 새는 거 아냐"입니다. 감추지 않고 무엇을
   맡기고 있는지 적고, 개인정보처리방침으로 잇습니다. 덧붙여 **그 두
   주소가 아닌 곳에서 온 인증 메일은 누르지 말라**고 적어둡니다 —
   설명하는 김에 피싱까지 막습니다.
2. **답답함** — 비밀번호가 틀렸는지 계정이 없는지 안 알려주는 것, 메일이
   자주 안 나가는 것, 링크가 죽는 것. 전부 까닭이 있는데 까닭을 말하지
   않으면 그냥 못 만든 로그인입니다.

⚠️ 이 글의 숫자와 문장은 두 곳과 어긋나면 안 됩니다 —
Supabase 대시보드 설정(Rate Limits · Email OTP Expiration)과
`/privacy` 제5조(위탁 목록). 한쪽만 고치면 화면이 거짓말을 합니다.

### 낯선 주소를 아예 줄이는 법 (설명보다 이게 낫습니다)

| 보이는 자리 | 없앨 수 있나 |
|---|---|
| 메일 **발신자** `noreply@mail.app.supabase.io` | ✅ 커스텀 SMTP 를 붙이면 우리 주소가 됩니다 (아래 참고) |
| 메일 속 **링크 주소** `<프로젝트>.supabase.co/auth/v1/verify…` | Supabase 커스텀 도메인 애드온(유료)이 있어야 바뀝니다 |
| 소셜 로그인 도중 주소창 | 위와 같음 |

커스텀 SMTP 는 어차피 붙여야 하는 것이고(아래), 붙이면 제일 무서운
자리인 발신자가 함께 해결됩니다.

## 소셜 로그인 (카카오·구글)

한 번에 끝납니다. 실패하면 사유만 띄웁니다 — 이 갈래는 우리 화면에서
할 수 있는 일이 없어서 길을 내지 않습니다 (다시 누르면 됩니다).

## ⚠️ 메일 발송 한도 — 오픈 전에 확인하세요

"메일을 너무 자주 보냈어요"는 우리 코드가 아니라 **Supabase 의 기본 메일
발송 제한**입니다. 기본 메일 서버는 개발용이라 한도가 아주 낮습니다
(시간당 몇 통). 실서비스에서 가입이 몰리면 **인증 메일이 아예 안 나갑니다.**

→ 유료 오픈 전에 **커스텀 SMTP** 를 붙이세요.
Supabase → Authentication → Emails → SMTP Settings.
(Resend · Amazon SES · Postmark 같은 곳)

붙이기 전까지는 테스트 계정으로 여러 번 시도하면 금세 막힙니다. 막혔을 때
당장 풀려면 Supabase → Authentication → Users → 해당 사용자 →
`Confirm email` 로 인증 상태를 손으로 만들 수 있습니다.
